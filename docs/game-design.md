## 1. 游戏定位

**一句话：从局部开始培育繁荣，改善人们的生活，直到实现全面现代化。**

玩家在一张全部格子均可居住的地图上，领导一块区域，对陆地进行农业、工艺、生产习惯或制度干预。人口、文化和制度根据上下左右邻格的状态自动变化。玩家观察结果，选择下一次干预。

游戏的主要体验是：人口更多不一定意味着生活更好；提高个人的生活质量不一定容易延续文明；一种开始时脆弱的制度可能通过长期增长获得优势，并借助原先对它不利的竞争机制向外传播。

| 项目 | 首版约定 |
| --- | --- |
| 类型 | 单人、局部干预策略、空间经济模拟 |
| 模型 | 多变量元胞自动机；邻域局部交互、分阶段同步更新 |
| 地图 | 24 × 16 格，共 384 格；固定矩形边界 |
| 操作 | 每轮选择一个地块执行一个行动 |
| 节奏 | 一轮推进 5 个世代，最多 50 轮／250 世代 |
| 单局时间 | 目标 15—20 分钟，包含观察与决策，待试玩校准 |
| 美术 | 二维俯视图；地块、房屋、灯光、制度纹样、迁移光点 |
| 发布 | 单机；TapTap 制造 |

### 1.1 理论与游戏改编的边界

游戏受吴乐旻《富种起源》的二元模型、族群竞择和制度竞择研究启发。下面的公式、制度命名、迁移方式、参数与胜利条件是游戏设计，不是原著公式的直接复刻。

| 理论关系 | 游戏中的对应体验 |
| --- | --- |
| 生存消费与个人福利不同 | 食物支持自然人口变化；生活用品提高生活品质 |
| 个体选择与群体传播结果可能不同 | 居民追求更好生活，迁移到生活质量高的地区又会改变人口密度和生产倾向，进而降低当地的生活质量 |
| 当前生存能力与长期增长存在权衡 | 探索型制度的动员效率较低，但工艺增长较快、主动改良成功率较高 |
| 竞择方向可能逆转 | 制度依实际竞争力传播，增长积累可改变传播方向 |

不能预设“移民必然有害”“探索型永远获胜”或“某个世代必然进入现代增长”。它们是否发生，要由规则和初始条件决定。用实际模拟产生的事件解释历史，不用固定剧情伪装成涌现。

## 2. 核心循环与玩家决策

```text
观察地图与变化记录
    → 选择并确认一次干预
    → 自动推进 8 个世代
    → 查看人口、福利和制度变化
    → 下一轮决策
```

每轮只能执行一次干预，制度保护也是独立行动，不能附加到其他行动，没有金币或建造队列。所有行动开局可用；可取消选择，确认后不能撤销，只能重新开始同一种子。

玩家每轮可选择地图内任意一个地块干预，不拥有固定国家。选择框仅覆盖点击的这一格，边缘同样适用。模拟播放时可暂停、检查和切换图层，但不能额外干预。

所有行动（含制度保护）仅作用于所选的一个地块，保护持续本轮的 5 个世代，界面显示所选坐标。无效行动不消耗回合、保护次数或随机数。

| 行动 | 确认后立即执行 | 限制及取舍 |
| --- | --- | --- |
| 农艺改良 | 抽签成功时，所选地块 `A *= 1.12`；失败无改良增幅 | 成败均消耗一轮；更多产出可能被人口增长吸收 |
| 工艺改良 | 抽签成功时，所选地块 `B *= 1.15`；失败无改良增幅 | 成败均消耗一轮；不直接提高自然人口增长 |
| 改变习惯 | 所选地块 `f += 0.10` 或 `f -= 0.10`，随后限制到合法范围 | 两个方向二选一；不能同轮改制度 |
| 制度试验 | 所选地块制度设为探索型 | 不立即赠送技术或财富；所选地块已是探索型时禁用 |
| 制度保护 | 所选地块 `protectionTicks = max(原值, 5)` | 单独选择并确认，占用一轮；全局最多 3 次；只降低外来制度替代概率，不阻止迁移 |

农业劳动比例 `f` 限制在 `[0.25, 0.85]`。改变习惯若不能改变所选地块，则对应方向禁用。制度试验只提供建立探索型的操作；动员型通过世界竞争继续存在和传播，首版不另做玩家主动切回动员型的按钮。

两种主动改良共用成功率：动员型 **10%**，探索型 **30%**，按确认时的地块制度判定。每次合法尝试从固定模拟随机流抽取一次；抽中才执行增幅，失败仍占用一轮并演进 5 世代。自然技术增长和邻格学习保持原规则，因此尝试失败之后也可能出现正常增长。制度保护不能与改良、投入调整或制度试验同时执行，不会提高改良成功率。

行动记录保存抽签前后随机状态、当时制度、概率、抽签值和结果，重放重新计算并核对；旧版确定性改良记录明确拒绝。界面展示所选地块成功率及最近一次行动的改良结果，推荐按成功与失败两条分支的预期收益评分，不提前读取抽签结果。

玩家典型决策：

- 食物不足时，先投资农业，还是调整劳动投入？
- 一片生活较好的区域吸引人口后，继续发展工艺，还是缓解温饱压力？
- 什么时候启动制度试验？先扩大经济规模，还是尽早积累增长？
- 探索型受到竞争压力时，继续发展还是消耗有限的保护机会？
- 将行动集中在一个核心区，还是扶持多个可能存续的区域？

## 3. 空间与元胞状态

### 3.1 空间规则

- 一格是一小片居住和生产土地，不是一个居民，也不是一个完整国家。
- 使用上下左右四邻域，不含对角线。
- 边界不环绕，左边不连接右边。
- 每个世代人口和制度最多传播一格，不进行全地图搜索。
- 所有格子均有人居住；不做海洋、荒地殖民和人口灭绝后的重建。
- 模拟不建立国家／城市对象。同色区域只是可观察的空间分布，不自动共享粮食、人口或竞争力。
- 开局地图划分为四片有名称的连续地区。地区是固定的地理识别信息，不是国家或资源共享单位，边界不阻挡迁移、制度或技术传播，玩家可选择任意地区中的一个地块干预。
- 平原、丘陵与山地按独立高度场成片生成，可以横跨地区。地形影响软承载量与每世代迁移人数，全部可居住、可通行。
- 三类地形均保持四邻域，人口迁移、技术学习及制度传播不被地形阻断；没有河岸产出加成。

```text
      上
      │
左 ─ 本格 ─ 右
      │
      下
```

### 3.2 数据结构

以下 TypeScript 风格结构只用于定义数据，不限定开发语言或引擎。

```ts
type Institution = "mobilize" | "explore" | "none"; // none 仅用于无人河格

interface CellState {
  population: number;       // N > 0，浮点人口单位
  agriculture: number;      // A > 0，农业效率
  craft: number;            // B > 0，工艺效率
  foodShare: number;        // f ∈ [0.25, 0.85]
  institution: Institution;
  protectionTicks: number;  // 非负整数
}

interface CellTerrain {
  baseLandCapacity: number; // 地区决定的基础容量，开局后固定
  landCapacity: number;     // K = 基础容量 × 地形倍率，开局后固定
  terrainKind: "plain" | "hill" | "mountain";
  elevation: number;       // [0,1] 相对高度，不是真实海拔
  migrationMultiplier: number; // (0,1]，跨边取两端较小值，不删除邻接边
}

interface CellMetrics {
  effectiveLabor: number;   // L
  foodOutput: number;       // F
  craftOutput: number;      // C
  foodRatio: number;        // s，人均食物，1 表示基本温饱
  craftPerCapita: number;   // c，人均生活用品
  attractiveness: number;  // U，迁移吸引力
  power: number;            // P，竞争力
}
```

地形、元胞状态、派生指标与表现动画分开存储。首版不保存粮食库存，不模拟年龄、家庭、职业个体和人物寻路。

## 4. 模拟规则

### 4.1 生产与生活品质

每人每世代需要 1 单位食物。产出在当期消费，不跨世代存储。

```text
L = N / (1 + N / K)
F = A × f × L
C = B × (1 - f) × L
s = F / N
c = C / N
```

`L` 表示受土地拥挤限制的有效生产规模。这里为了首版可实现性，两部门共用这一拥挤项。

`K` 是软承载量，不是人数上限。允许 `N > K`，不截断人口，不禁止迁入或出生；拥挤通过人均产出、温饱、自然增长和迁移调节。同样人口住在容量较小的山地，人均食物和生活用品都会较低。改善农艺仍可提高温饱，地形不另加缺粮惩罚。

以上公式统一用于所有格子，不含地理产出加成。

结果：人口增加会提高总产出，但总产出增长小于人口增长，因此人均产出下降。农业投资直接增加食物，工艺投资直接增加生活用品，改变 `f` 会在两部门之间重新分配劳动。

在技术、制度和生产比例固定，且没有迁移的条件下，`s = 1` 时：

```text
N* = K × (q × A × f - 1)    // 仅在 q × A × f > 1 时存在正人口均衡
c* = (B / A) × ((1 - f) / f)
```

这解释了为什么长期人均结果取决于生产结构和相对效率。若 `A × f <= 1`，本地无法靠该组合维持正的温饱均衡，应通过持续缺粮表现，不把公式得到的负数当成人口。

### 4.2 自然人口增减

根据当期生产计算自然增长率：

```text
g = 0.50 × tanh(2 × (s - 1))
N_afterNatural = N × (1 + g)
```

- `s > 1` 时自然增长，`s < 1` 时自然减少。
- 单世代自然增减幅度不超过 50%；同一系数同时控制粮食盈余时增长和缺粮时减员。
- 生活用品不直接影响自然增长率。
- 先完成所有格子的自然变化，再进入迁移阶段。
- 不将人口四舍五入，不设置会凭空补充人口的整数下限。绘制与文本可以取整，内部保留浮点数。

### 4.3 人口迁移

#### 4.3.1 计算生活吸引力

使用自然增减之后的人口重新计算生产与人均指标：

```text
U_i = ln(1 + c_i) - 4 × max(0, 1 - s_i)
```

生活用品提高吸引力，严重缺粮降低吸引力。食物超过温饱后，不再直接当作生活品质奖励。

模拟邻接表包含全部上下左右相邻边，采用固定边界，不连接对角线，也不绕回地图另一侧。三类传播均逐格、同步结算。

#### 4.3.2 计算迁移意愿

对本格 `i` 的每个邻格 `j`：

```text
d_ij = max(0, U_j - U_i - migrationCost)
migrationCost = 0.10
D_i = Σ_j d_ij
```

`migrationCost` 表示迁移阻力。只有生活差超过这项阻力才迁移，未参与比较的远处格子不影响决策。

#### 4.3.3 计算迁出总量与方向

```text
若 D_i = 0：所有 M_ij = 0
否则：
  O_i = N_i × 0.24 × D_i / (1 + D_i)
  t_ij = min(本格迁移效率, 邻格迁移效率)
  M_ij = O_i × d_ij / D_i × t_ij
```

`O_i` 为地形折减前的迁出意愿总量，单世代小于人口的 24%；实际迁出量为 `Σ M_ij`。一个来源可同时向多个邻居迁移。地形减慢某条边时，未迁出的居民留在来源，不转分给其他方向。没有目的地硬性接收上限；拥挤通过下世代人均产出和吸引力反馈。

#### 4.3.4 同步迁移

```text
N_i' = N_i - Σ_j M_ij + Σ_j M_ji
```

先生成完整迁移流量表，再同时更新人口。所有流量只能读取迁移前快照，禁止迁入者在同一世代再次迁出。

**迁移阶段全球人口总量必须守恒。**出生死亡属于上一阶段，不能混入迁移守恒检查。

例：甲有 100 人，只有乙一个邻居，甲乙吸引力分别为 0.40、0.90。扣除迁移阻力后 `d = 0.40`。两端均为平原时，本世代迁移 `100 × 0.24 × 0.40 / 1.40 ≈ 6.86` 人口单位；一端为山地时，乘以 0.40，实际迁移约 2.74，差额仍留在甲。

迁移不是固定路线。甲迁出后拥挤减轻，乙迁入后拥挤增加；下世代重新计算，流量可能减弱或改变方向。

### 4.4 迁移携带的文化变化

首版用农业劳动比例 `f` 代表可传播的生产倾向。迁入者保留部分来源格习惯，缓慢影响目的地。

```text
I_i = Σ_j M_ji

若 I_i = 0：f_i' = f_i
否则：
  incomingFoodShare = Σ_j(M_ji × f_j) / I_i
  f_i' = f_i + 0.50 × (I_i / N_i') × (incomingFoodShare - f_i)
```

所有 `f_j` 读取迁移前快照。迁入与迁出的本地居民不存在额外个人属性，因此本地剩余人口仍使用原本的 `f_i`。文化混合与人口迁移在同一阶段完成。

例：迁入后总人口 100，其中新迁入 10；本地 `f = 0.40`，移民平均 `f = 0.70`，则本地变为 `0.415`。

文化传播不删除技术、不直接切换制度，也不固定向农业倾斜。来源不同，影响方向不同。迁入带来总生产能力，也带来人口消费与拥挤，不能把迁移硬编码成福利惩罚。

### 4.5 技术增长

| 参数 | 动员型 | 探索型 |
| --- | ---: | ---: |
| 每世代农业效率增长 | 0.2% | 0.2% |
| 每世代工艺效率增长 | 0.2% | 1.5% |
| 主动农业 / 工艺改良成功率 | 10% | 30% |
| 动员系数 `m` | 1.00 | 0.75 |

```text
A_next = A × (1 + 本地制度对应的农业自然增长率)
B_next = B × (1 + craftGrowth)
```

两种制度均保留自然技术增长。探索型工艺增长恢复至每世代1.5%，并提高主动农业与工艺改良的成功率，付出当前动员能力的代价。制度改革不立即赠送技术；本世代末发生的制度替代从下一世代影响技术增长。这些比例是游戏平衡参数，并非原著的历史增长率。

### 4.5.1 邻格技术学习

每世代原有技术增长后，农业与工艺分别读取自身和四邻格的最高效率，学习技术差距的 5%：

```text
A_next = A + 0.05 × max(0, max_neighbor_A - A)
B_next = B + 0.05 × max(0, max_neighbor_B - B)
```

先计算全部格子的学习增量，再一起提交；同世代不会把刚学到的技术继续传两格。学习不消耗随机数，也不复制人口或制度。世代记录保存来源、类型和实际增量，供地图与详情显示。

### 4.6 制度竞争

技术增长后，重新计算产出和竞争力：

```text
P_i = m_i × (F_i + 0.50 × C_i)
```

生活用品经济也能贡献竞争力，否则探索型无法通过经济积累弥补当前劣势。系数只用于抽象这种转化，首版不再开发财政、市场和税制。

每格执行一次竞争判断：

1. 从四邻域中选择竞争力最高的格子 `j`；若并列，用固定随机种子选择。
2. 若 `j` 与本格制度相同，或 `P_j <= P_i`，不发生制度替代。
3. 否则计算 `p = 0.20 × (P_j - P_i) / (P_j + P_i)`。
4. 本格受保护时，`p *= 0.25`。
5. 进行一次随机判定；成功则采用 `j` 的制度，并令 `f_i = 0.80 × f_i + 0.20 × f_j`。

全部判断基于同一快照，最后同时应用。每格每世代至多替代一次。替代保留人口与技术，不触发额外财富、战争伤亡和土地吞并。

本版本的制度竞争是抽象的邻近替代机制，不将每次替代都叙述为战争。传播速度来自实际竞争力、邻接关系与概率，不采用多数邻居投票。

### 4.7 保护效果

- 单独确认制度保护时，将所选地块计时设为至少 5，并消耗一轮和一次保护机会。仅选择或取消不扣次数；无效行动不改变世界、次数或随机数。
- 每个世代竞争时，`protectionTicks > 0` 即生效。
- 完成该世代竞争后，计时减一，最低为 0。
- 因此保护覆盖行动之后完整的 5 次竞争结算。
- 不改变人口迁移、自然增长、文化混合或技术增长。

## 5. 完整结算顺序

```ts
function tick(world, rng) {
  const afterNatural = applyNaturalGrowth(world);
  // 上一步内部以旧人口计算产出，再同时更新所有人口。

  const migrationMetrics = calculateMetrics(afterNatural);
  const flows = calculateAllMigration(afterNatural, migrationMetrics);
  const afterMigration = applyMigrationAndCulture(afterNatural, flows);

  const afterGrowth = applyTechnologyGrowth(afterMigration);
  const afterLearning = applyNeighborLearning(afterGrowth);
  const competitionMetrics = calculateMetrics(afterLearning);
  const changes = calculateInstitutionChanges(
    afterLearning, competitionMetrics, rng
  );
  const next = applyInstitutionChanges(afterLearning, changes);

  decrementProtection(next);
  const finalMetrics = calculateMetrics(next);
  recordHistory(next, finalMetrics, flows, changes);
  evaluateGameProgress(next, finalMetrics);
  return next;
}
```

每个阶段同步更新，但后一个阶段可以读取前一个阶段的完整结果。只禁止同一阶段中，先更新的格子影响尚未更新的格子。

随机数使用可复现种子。动画不调用模拟随机流；暂停、帧率和图层切换不改变结果。遍历使用固定格子顺序；记录初始种子、参数版本和玩家行动，可重放一局。

## 6. 开局生成与参数配置

首版生成全陆地地图。起始经济避免普遍严重饥荒，同时保留少量差异。

| 项目 | 起始范围或规则 |
| --- | --- |
| 基础容量 | 32—48；实际 `K = 基础容量 × 地形倍率` |
| `A` | 2.8—3.2 |
| `B` | 1.8—2.2 |
| `f` | 0.50—0.65 |
| `N` | `K × (A × f - 1) × random(0.90, 1.10)` |
| 制度 | 大部分动员型；4 个互不重叠的 2×2 探索型试验区 |
| 保护 | 0 |

初始探索区位置由种子决定，分散放置。每个象限保留原来的两次随机抽样，从抽中的位置有限扫描完整陆地 2×2 候选，避开河格；无法容纳时明确拒绝该自定义地图配置，不无限重抽。它们让玩家无需先做制度试验，也能观察自然存续与替代；系统不保证任何一个区域成功。首版不额外加入随机制度突变。

### 6.1 程序化特色地区（origin-1.2.0）

开局先用独立随机序列生成四片不规则的四邻域连通地区，覆盖全部 384 格。四种特点在不同种子下交换位置，轮廓也随种子变化；同种子重开时名称、边界、初始数值全部一致。名称由方位与地区名组成，例如“西北百工镇”。名称代表点始终属于该地区。

| 地区 | 开局特点 | 可观察的取舍 |
| --- | --- | --- |
| 丰禾乡 | 农业效率较高，人口略低于温饱平衡 | 食物略有余裕，生活用品基础相对一般 |
| 百工镇 | 工艺效率较高，务农比例较低 | 人均用品较好，需观察食物与迁入人口的变化 |
| 万家聚 | 同地形下基础容量较高，人口较多且略超温饱平衡 | 一次干预影响的人口较多，开局温饱有轻微压力 |
| 疏居地 | 同地形下基础容量、人口、农业与工艺基础较低 | 人少、发展基础较弱，位置与邻近地区影响其发展机会 |

每片地区仅改变上表原有参数范围内的抽样分位，并保留小幅逐格扰动。农业、工艺、习惯与基础容量不超出 §6 的既有范围；人口按实际 `K × (A × f - 1) × noise` 生成。农业余裕来自较低人口扰动，人口压力来自较高扰动，不能把农业效率高直接等同于永远不缺粮，也不能忽略地形比较不同地区的人口。

地区参数集中在 `scripts/OriginRegions.lua` 的 `PROFILES`，每格仍固定使用原来的五次模拟随机抽样。轮廓、名称和标签布局使用独立数据，不消耗制度竞争的随机流。地区身份没有永久加成，也不增加行动、库存或建筑；地形对承载与迁移的影响另见 §6.2—6.3。

界面仅以地名和地区分界线区分地区，不添加烟囱、小树或额外田埂等地区专属装饰；生活品质、人口、制度图层仍显示当期状态。详情面板明确标注“开局”特点，后续数值变化以实时指标为准。地名只在真实代表点可见且不重叠时绘制，镜头外地名不吸附到错误位置；点击任意格仍可在详情看到其地区名。

### 6.2 程序化地形与软承载量

用户确认采用软承载量。地形使用独立随机序列，由平滑的主高度场与小幅细节组成，按高度分位成片分布。地形不绑定地区名称，不消耗世界演化随机数，同种子地形一致。

从 origin-1.7.0 起，以全图总格数 `N` 为分母，严格满足 **平原 >60%、山地 <15%**，其余为丘陵。平原生成 `ceil(0.68N)` 格，山地生成 `floor(0.14N)` 格，其余为丘陵；不再生成河流。高度场细节权重为10%，避免过窄的丘陵带产生零散单格。小地图允许缺少山地或丘陵，优先满足严格比例。

| 地形 | 承载量倍率 | 迁移效率 |
| --- | --- | --- |
| 平原 | 1.50 | 100% |
| 丘陵 | 1.00 | 70% |
| 山地 | 0.50 | 40% |

这些是集中在 `OriginConfig.lua` 的初版参数，仍需真人试玩校准。实际软承载量取地区基础容量乘以地形倍率；初始人口也按实际容量生成，使同一经济格的初始拥挤程度和人均温饱不因地形类型骤变。后续人口变化时，地形容量持续影响拥挤反馈。

迁移速度在模型中表示每世代实际迁移人数，按 §4.3 的两端较慢效率计算；不加入在途人口、等待队列、道路或额外行动。以上三种陆地均可居住通行；不额外修改技术学习率或制度替代概率，但人口规模变化仍会通过原有公式影响竞争力和人口加权统计。三类地形均使用同一四邻域。

地图用连续地貌底图区分地形，农田不再按地形或地区改变外观；原统计图层颜色不变。地块详情显示类型、实际软承载量、承载倍率和迁移效率；光点速度同步表现通行差异。地形、容量及通行率写入迁移前快照与逐世代重放；旧版本行动记录明确拒绝，避免静默套用新规则。

### 6.3 完整四邻域与版本

按用户调整移除河流、不可居住格、传播屏障和河岸25%加成。每个格子都执行相同的生产、增长、迁移、技术学习和制度竞争步骤；地形只影响软承载量和迁移人数，不删除邻接边。所有行动作用于整个方形选区；当前正式选区为单格。

当前生成版本 `origin-terrain-5`，模型版本 `origin-1.10.0`。旧版行动记录不能静默套用新规则；旧农业单字段 `agricultureGrowth` 已拆为 `mobilizeAgricultureGrowth` 与 `exploreAgricultureGrowth`，旧单字段与已删除的河流配置会报未知参数。自定义规则的重放必须携带完整世界配置。以前的截图与验收记录保留为历史证据。

所有参数集中配置，禁止散落在表现代码。至少包括：地图尺寸、回合数、每轮世代数、行动区域尺寸、投资增益、生产比例范围、自然增长系数、迁移成本与上限、文化影响系数、技术增长率、动员系数、竞争系数、保护时长和胜利门槛。

## 7. 目标、观察期与结算

### 7.1 统计口径

开局在任何玩家行动之前，计算人口加权的世界平均生活用品：

```text
c0 = Σ_i(N_i × c_i) / Σ_i N_i
```

此基准整局固定。一个格子同时满足下列条件，计为繁荣格：

```text
s_i >= 1
c_i >= 2 × c0
```

世界繁荣人口占比：

```text
prosperousShare = 繁荣格人口之和 / 世界总人口
```

不按格子数计算，避免人口极少的富裕区域抬高成绩。

### 7.2 胜利条件

繁荣人口占比连续 5 个世代达到 80%。

10%／30%／60% 是中途里程碑，首次达到时提示，按历史最高值保留。里程碑不降低胜利门槛；当期繁荣低于 80% 时，连续达标计数仍归零。

### 7.3 非胜利结果

正常 250 个世代结束且未达成胜利条件。

结算展示：最高繁荣人口占比、繁荣人口占比变化曲线、世界人均生活用品曲线、探索型人口占比变化曲线。

### 8.3.1 繁荣短板与技术反馈

按人口将全世界分为四个互斥类别：繁荣、用品达标但缺粮、温饱达标但缺用品、两项均不足，合计 100%。地图上方显示后三类，趋势面板说明完整口径；地块详情显示本格短板与本世代从邻格学到的农业、工艺增量。提示只根据当前短板给方向，不预言下一轮结果。

技术流使用完整的蓝色小箭头带渐隐拖尾一起移动。抵达目标后停住，透明区域从拖尾到箭尖逐步扩张，完全透明时完成本次换代，不再循环重播。移动阶段的箭尖和短箭身保持完整、实色，不使用固定透明箭头或裁剪流光。移动与透明区域扩张共用同一条路径上的像素线速度：移动与消失的总时长由 `scripts/OriginEvolution.lua` 的 `GenerationSeconds` 统一控制，默认1倍速4秒；根据路径、箭身与拖尾长度分配移动和消失时间，不另设更快的擦除速度。移动和消失都使用同一个由透明到蓝色的线性渐变，消失时只将拖尾渐变向前平移，渐变长度始终保持28%路径长度，不压缩成窄边。浅蓝表示农业，深蓝表示工艺，所有传播使用同一代的累计进度。勾选“技术流”显示全图本次换代的真实传播；取消勾选只保留当前所选地块与上下左右邻格之间的传入与传出。全图缩放也显示，微弱传播不因增幅阈值被隐藏。接收方本次技术相对增幅越大，完整箭头与拖尾越粗；正常格宽的箭身宽度约0.85～9，使用 `gain / (gain + 0.0010)` 拉开常见增幅的粗细差，极强传播平滑封顶，所有尺寸随格宽适配。两种技术及反向传播使用不同通道，显示开关和动画不改变模拟。

人口迁移使用金白色亮芯、柔和暖金光晕与短尾迹，沿本次换代的真实迁移边移动。完整动画同样占用一代的时间，前75%移动至终点，后25%让光点、光晕与拖尾一起渐隐；到期后不重播。地形仍影响真实迁移量，不再单独改变光点播放周期。小流量也保持最低可见尺寸和亮度，流量越大光点越大；全图视角不再隐藏。迁移勾选框独立控制这些光点，动画不改变人口、流量或模拟随机数。

换代时序：确认干预后，在独立副本上调用一次正式模拟，得到待展示的真实流动；当前世界、世代编号与统计在动画期间保持本代状态。动画时长结束才提交已计算的结果，避免首代空等或轮末动画缺失。上一代历史不重复计算，提交结果与直接模拟一致。决策与结束界面不保留流动动画。1×每代4秒、每轮5代20秒；2×为2秒/代；4×为1秒/代。暂停、弹窗和竖屏阻挡冻结同一进度；点击切换倍速只影响后续时间，不重置或跳跃动画。帧间隔仍最多计入0.25秒，每帧至多完成一代；低帧率可能延长实际播放时间，不跳过世代。

## 9. 验证与风险

### 9.1 先完成三个开发实验场景

| 场景 | 开启内容 | 验证目标 |
| --- | --- | --- |
| 单格经济 | 生产、自然人口；可关闭技术增长 | 验证人口反馈与两部门投资差异 |
| 迁移实验 | 相邻格、固定制度、文化混合 | 验证迁移守恒、拥挤反馈和来源文化影响 |
| 完整制度实验 | 全部规则 | 验证改革早期失败与增长积累后扩散都可能发生 |

实验场景是开发工具，不要求制作成三个正式模式。

### 9.2 必须通过的实现检查

- 迁移单独结算时总人口在浮点容差内守恒。
- 同一阶段更新结果不受提交写入顺序影响，不出现单世代跨多格迁移。
- 所有人口、效率和竞争力有限且有效，无负人口、NaN 或无穷值。
- `f` 始终位于合法范围，零迁入时文化混合不发生除零。
- 对称的相同格子不自行产生迁移；不足迁移成本的差异不引发流动。
- 同种制度不发生无意义替代；保护恰好覆盖指定次数的结算。
- 相同种子、配置与操作能重放相同结果；帧率和动画不影响模拟。
- 全球指标按人口加权，胜利基准固定，观察期不能重复赠送行动。

### 9.3 主要风险与调整顺序

| 风险 | 优先排查或调整 |
| --- | --- |
| 改革区总是立即消失 | 降低竞争强度、缩小动员劣势、检查保护与结算时序 |
| 探索型自动必胜 | 调整初始分布、增长优势和动员劣势；比较无干预基线 |
| 迁移量小到不可见 | 先提高光点可读性，再调整迁移成本与流量，不能只靠放大伤害 |
| 人口拥挤过强，所有地方持续饥荒 | 检查 `A × f`、人口增长率和初始人口 |
| 只有工艺投资有效 | 检查温饱约束是否实际生效，以及农业和习惯行动是否提供真实帮助 |
| 地图迅速变得完全相同 | 检查文化影响、竞争概率和技术增长差异，保留空间异质性 |
| 玩家看不出因果 | 优先补分项记录、检查面板和速度控制，不新增资源 |
| 富裕达标但无需制度扩散 | 比较多种种子与行动记录，调整局长、门槛及制度收益；不强制指定获胜制度 |
