# 农业与工艺改良：制度影响成功率

> 验证资料管理：本文保留结论与复现方法；原始截图、日志、逐局记录和冻结源码仅存于 Git 忽略的 `.tmp/`，不随云端提交。历史记录路径仅供本地排查，清理后可按脚本、参数和版本重新生成。

当前规则版本：`origin-1.10.0`，支持[开局参数设置](game-settings.md)。默认动员型 **10%**、探索型 **30%**；探索型自然工艺增长为每世代1.5%，动员型为0.2%，人口自然增减上限50%，迁移上限24%。下列 v1.9.1 通关数据为历史结果，后续固定参数结果见 `population-growth-balance.md`，不适用于任意自定义参数。

两种改良使用同一组概率，按确认时所选地块的制度判定。成功保留农业效率 +12%、工艺效率 +15%；失败不获得本次改良增幅，仍消耗一轮并演进 5 世代。邻格学习、50 轮上限和胜利条件不变；两制度自然农业增长均为0.2%，自然工艺增长分别为0.2% / 1.5%。制度保护已改为独立行动，不能与改良同时执行；改良成败均不消耗保护次数。

每次合法改良只抽签一次，预览、切换选区和推荐不会消耗随机数。行动记录保留制度、概率、抽签值、成败及前后随机状态，重放重新计算核对。相同种子和相同行动仍然可复现；旧版本完整记录不会静默按新规则执行。

界面显示当前地块的制度与成功率；确认后显示结果，并保留到本轮演进结束。失败不会被记作玩家带来的温饱或技术成果。推荐按成功与失败两条分支计算预期收益。

默认种子 `20261002`：跟随推荐在第 225 世代通关（原来 201）；温饱阈值策略未通关（原来 195）；制度网络策略第 176 世代通关（原来 178）。推荐和后期收益选点已同步考虑成功率，因此这里比较的是每个版本实际使用的策略。

这组结果表明原先稳定的集中改良打法明显变难，制度路线仍强。不能解释为所有玩法、所有地图都更难：改良抽签也推进了模拟随机流，改变后续制度竞争，而且较少工艺投入可能缓解温饱压力。只改工艺的通关数反而有所上升。10 张地图不是总体胜率估计。
